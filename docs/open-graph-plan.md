# 오픈 그래프 적용 계획

- 작성일: 2026-09-24
- 작업 브랜치: `design/blog-refresh`
- 상태: 구현·로컬 검증 완료, 배포 후 외부 카드 검증 대기
- 범위: 한국어·영어 홈페이지, 블로그 목록, 개별 글의 공유 미리보기
- 후속 요청으로 구현을 완료했다. 커밋·푸시·배포는 하지 않았다.

## 1. 목표와 현재 상태

홈페이지나 글 주소를 공유했을 때 해당 페이지에 맞는 제목·설명·대표 이미지가 표시되도록 한다. 사이트 이름은 상단 로고와 같은 `Wonjin`으로 통일한다.

현재 홈페이지 2개, 블로그 목록 1개, 글 56개로 총 59개 페이지가 있다. 기본 제목과 설명은 있지만 Open Graph 태그와 전용 공유 이미지는 없다. 모든 글에 원본 description이 있으며, 그중 48개는 160자를 넘는다.

공개 홈페이지 주소는 `https://choiwonjin55.github.io/`로 확인했다. 블로그는 `build_blog.py`가 `posts/*.md`를 읽어 생성하므로 생성 원본에 메타정보를 추가한다.

## 2. 1차 적용안

먼저 대표 이미지 3종으로 전체 페이지를 지원한다. 개별 글은 각각 다른 제목·설명을 사용하고, 이미지가 따로 지정되지 않으면 블로그 공통 이미지를 사용한다.

| 대상 | 공유 제목 예시 | 설명 | 이미지 |
| --- | --- | --- | --- |
| 한국어 홈 | Wonjin · 데이터 사이언티스트 최원진 | 현재 한국어 소개를 1~2문장으로 요약 | `home-ko-v1.png` |
| 영어 홈 | Wonjin Choi · Data Scientist & AI Engineer | 현재 영어 소개를 영어로 요약 | `home-en-v1.png` |
| 블로그 목록 | Research & Notes · Wonjin | 데이터 분석과 AI, 경제, 일상에 관한 생각을 기록합니다. | `blog-v1.png` |
| 개별 글 | 정리된 원본 글 제목 | 해당 글의 요약 | 지정 이미지 또는 `blog-v1.png` |

제목·소개 문구는 초안이다. 본문의 이름, 글 내용, 화면 레이아웃은 유지한다. X용 카드 태그는 추가 호환 항목으로 함께 준비하며, 서비스별 최종 표시 형태는 배포 후 확인한다.

## 3. 대표 이미지 디자인

- 프로젝트 기본 규격은 1200×630px PNG로 정한다. 이는 제작 기준이며 Open Graph 자체의 필수 크기로 취급하지 않는다.
- 현재 사이트와 같은 흰 배경, 짙은 글자, 충분한 여백을 사용한다.
- 홈 이미지는 `Wonjin`, 직무, 한 줄 소개를 배치하고 한국어·영어 버전을 구분한다.
- 블로그 이미지는 `Wonjin`, `Research & Notes`, 짧은 소개를 배치한다.
- 핵심 글자는 중앙 영역에 두고 외곽에 최소 80px의 여백을 확보한다. 작은 카드와 잘린 미리보기에서도 읽히는지 확인한다.
- 파일 용량은 장당 500KB 이하를 목표로 최적화한다. 플랫폼의 보장된 제한으로 간주하지 않는다.
- 원본은 텍스트를 수정하기 쉬운 SVG로 관리하고 공유용은 PNG로 내보낸다. 새 한글 문구가 들어가도 글자가 깨지지 않는 렌더링 환경과 서체를 기록한다.
- `assets/og/`에 저장한다. 이미지 변경 시 버전이 포함된 새 파일명을 사용하고 해당 메타정보도 갱신한다.

1차에서는 56개 글의 이미지를 각각 제작하지 않는다. 글별 제목이 들어가는 카드 자동 생성은 후속 과제로 둔다.

## 4. 메타정보 규칙

### 공통 정보

초기 HTML의 `<head>`에 메타정보를 출력한다. 브라우저에서 JavaScript가 실행된 뒤 추가하는 방식은 사용하지 않는다.

- `og:title`, `og:type`, `og:url`, `og:image`: 기본 정보.
- `og:description`, `og:site_name`, `og:locale`: 페이지 요약, `Wonjin`, 언어.
- `og:image:alt`, `og:image:type`, `og:image:width`, `og:image:height`: 실제 이미지에 맞는 설명·형식·크기.
- `link rel="canonical"`: 해당 페이지의 대표 주소로 `og:url`과 일치시킨다.
- X용 보조 정보: `twitter:card=summary_large_image`, `twitter:title`, `twitter:description`, `twitter:image`, `twitter:image:alt`를 같은 데이터로 출력한다. 확인되지 않은 X 계정명은 넣지 않는다.

Open Graph의 기본 속성과 이미지 부가 정보는 [공식 프로토콜](https://ogp.me/)을 기준으로 한다. X 보조 태그는 구현 시 공식 문서 위치를 재확인하고 실제 플랫폼 검증 결과를 별도로 기록한다.

### 주소·언어·유형

| 페이지 | 대표 주소 경로 | 언어 | 유형 |
| --- | --- | --- | --- |
| 한국어 홈 | `/` | `ko_KR` | `website` |
| 영어 홈 | `/index-en.html` | `en_US` | `website` |
| 블로그 목록 | `/blog/` | `ko_KR` | `website` |
| 글 | `/blog/{slug}.html` | `ko_KR` | `article` |

페이지 주소와 이미지 주소는 모두 위 공개 도메인 기준 HTTPS 절대 주소로 만든다. `/index.html`과 `/blog/index.html`로 접근해도 각각 `/`, `/blog/`를 대표 주소로 사용한다. 기존 링크와 파일 경로는 유지한다. 영어 홈을 한국어 홈의 대표 주소로 합치지 않는다.

글에는 실제 원본 날짜로 `article:published_time`을 넣을 수 있다. 원본이 날짜만 제공하면 날짜 정밀도를 유지하며 시각을 만들어 넣지 않는다. 수정일은 실제 데이터가 있을 때만 출력한다.

## 5. 글별 설명과 이미지 선택

### 설명

1. 선택 필드 `og_description`이 있으면 우선 사용한다.
2. 없으면 현재 `description`을 사용한다.
3. 둘 다 없으면 본문에서 코드·표 등을 제외한 첫 일반 문단을 사용한다. 사용할 문장이 없으면 글 제목과 사이트 소개로 대체한다.
4. HTML 태그·엔티티와 연속 공백을 정리해 일반 텍스트로 만든다.
5. 프로젝트 기준 약 160자 이내로 요약 길이를 제한한다. 가능하면 문장 경계에서 줄이고, 잘린 경우 말줄임표를 붙인다. 플랫폼마다 표시 길이는 다를 수 있다.
6. HTML 속성에 출력할 때 따옴표·앰퍼샌드 등을 이스케이프한다.

160자는 운영상 목표이며 프로토콜의 글자 수 제한이 아니다. 원본 글이나 원본 description을 일괄 덮어쓰지 않는다. 기존 Tistory 글과 긴 영어 설명을 포함한 대표 샘플로 요약 품질을 확인한다.

### 이미지

1. 선택 필드 `og_image`로 지정한 사이트 내부 이미지가 있으면 사용한다.
2. 지정하지 않으면 블로그 기본 이미지를 사용한다.
3. 1차에서는 외부 이미지 URL을 받지 않고 `/assets/og/...` 같은 사이트 루트 기준 경로로 제한한다. 기존 글의 외부 이미지를 임의로 가져오지 않는다.
4. 별도 이미지를 지정할 때는 `og_image_alt`도 작성한다. 실제 파일 형식·가로·세로 크기를 읽어 메타정보를 만든다.
5. 명시한 이미지 파일이 없거나 지원하지 않는 형식이면 검증 오류로 알린다. 이미지 필드가 없는 정상 글은 기본 이미지를 사용한다.

이 선택 필드들은 기존 front matter의 단순한 `키: 값` 형식에 맞춘다. 기존 56개 글을 수정하지 않아도 기본 설정으로 빌드되어야 한다.

## 6. 파일별 작업과 순서

| 순서 | 파일 | 작업 |
| --- | --- | --- |
| 1 | `assets/og/` | 한글 홈·영어 홈·블로그용 SVG 원본과 PNG 3종 제작 |
| 2 | `build_blog.py` | 사이트 URL·기본 이미지 설정, 공통 메타 태그 생성 함수, 설명 정리·이미지 선택 처리 |
| 3 | `index.html`, `index-en.html` | 언어별 공유 메타정보와 대표 주소 추가 |
| 4 | `blog/index.html`, `blog/*.html` | 수정된 생성 스크립트로 재생성 |
| 5 | `scripts/check_social_metadata.py` | 전체 페이지의 필수 태그·주소·이미지·언어·대표 주소 검증 |

블로그 목록과 글은 같은 함수를 사용해 누락과 중복을 줄인다. 정적 홈페이지 2개는 직접 관리하되, 검증 스크립트가 생성기의 사이트 주소·기본값과 일치하는지 확인한다. 기존 메타 description은 불필요하게 교체하지 않는다.

- [x] canonical과 og:url이 같고 홈페이지·목록·글별 주소가 정확하다.

- [x] 기존 홈페이지·필터·글 본문에 의도하지 않은 변경이 없고 기존 URL이 유지된다.

### 배포 후 외부 미리보기 검증

외부 서비스는 localhost의 파일을 읽을 수 없으므로 실제 카드 검증은 사용자가 배포한 뒤 별도 진행한다. 현재의 커밋·푸시 금지 지시를 유지한다.

- 공개 페이지와 이미지가 인증 없이 HTTP 200으로 내려오고 적절한 Content-Type을 제공하는지 확인한다.
- [카카오 개발자 도구](https://developers.kakao.com/tool)의 URL 메타정보 관리로 주요 페이지를 확인한다. 이전 정보가 남아 있으면 해당 URL의 캐시를 초기화한다.
- 실제 카드의 표시·잘림 여부는 사용자가 카카오톡 나와의 채팅 등에서 확인한다. 이 계획은 메시지 자동 발송을 포함하지 않는다.
- 서비스마다 카드 표시·캐시가 다르므로 로컬 메타정보 검증 완료와 실제 플랫폼 검증 완료를 구분해 기록한다.

## 8. 후속 확장

1차 적용 이후 필요하면 글 제목·카테고리를 사용한 글별 이미지 자동 생성, 주요 글 전용 이미지 제작을 추가한다. 공유 버튼·SDK 도입, 사이트 디자인 재개편, 검색 최적화 전반은 이번 범위에 포함하지 않는다.


## 9. 구현 결과

- 59개 페이지에 Open Graph, canonical, X 카드용 태그를 초기 HTML로 출력했다.
- 공통 설정과 텍스트 정리·이미지 검증은 `social_metadata.py`로 분리했다.
- `scripts/update_home_social_metadata.py`가 공통 설정을 읽어 정적 홈페이지의 공유 정보 블록만 갱신한다. 블로그는 기존 `build_blog.py`에서 공통 함수를 사용한다.
- 대표 이미지 3종은 SVG 원본과 PNG로 저장했다. 모두 1200×630px이며 약 26~32KB이다. 원본 및 축소 이미지를 직접 확인했다.
- 커스텀 이미지는 1차에서 PNG를 지원한다. 외부 주소·상대 경로·없는 파일·대체 설명 누락은 오류로 처리한다.
- 기존 59개 페이지의 body 마크업이 작업 직전과 동일함을 확인했다. 글 원본은 변경하지 않았다.
- 전체 공유 메타정보 검증: 59개 페이지, 오류 0건.
- 원본/생성 검증: 56개 글, 오류 0건. 기존 Tistory 메타정보 경고 2개는 그대로 유지했다.
- 단위·생성 통합 테스트 5개 통과: 설명 선택 순서, 본문 대체 설명, 길이 제한, 이미지 기본값·실패 처리, 주소 검증, 특수문자·한글 출력.
- 운영 안내와 선택 필드 예시는 `assets/og/README.md`에 기록했다.
- X의 기존 공식 카드 문서는 일반 개발자 페이지로 이동하고 대체 주소도 열리지 않아 플랫폼 문서의 상세 규격을 재확인하지 못했다. 보조 태그를 구현했으며 실제 표시 검증은 배포 후 진행한다.
- 커밋·푸시·배포와 외부 서비스로의 메시지 발송은 수행하지 않았다. 실제 카카오톡/X 카드 확인은 미완료이며 배포 후 단계로 남긴다.


## 배포 진행 기록

후속 사용자 요청으로 최종 검증 → 커밋 → 작업 브랜치 푸시 → PR 생성·main 머지 → GitHub Pages 배포 확인까지 진행한다. 앞선 커밋·푸시 보류 기록은 각 단계 당시의 상태이다.

배포 전 확인: 원격 main과 작업 브랜치의 기준 커밋 일치, 생성된 글 56개와 공유 정보 59개 페이지 검증 오류 0건, 테스트 5개 통과. 기존 Tistory 메타정보 공란 경고 2개는 그대로 유지했다. 실제 서비스 배포와 공개 URL 검증 결과는 PR 및 배포 실행 기록에서 확인한다.
